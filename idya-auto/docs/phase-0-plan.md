### A9. SMS provider

§12 mentions optional SMS to sales. Twilio, or skip for v1? Default: skip; email only.

### A10. Natural-language search cache

"Identical queries cached 24 h" (§27.2): a Postgres table (`search_cache`, no new vendor) or

### A11. Definition of "first token in < 1.5 s" (§25)

When the assistant must call a tool first, the first *text* token can arrive after 1.5 s even
with a fast model. Proposal: measure time to first visible response (typing indicator or

replies that need no tool. Please confirm.

## C. Technical review of the brief

Numbered so each item can be approved or declined individually. **Fix** = I believe the brief
is wrong. **Better** = the brief works but there is a stronger option. **Note** = no change
requested, just a risk you should know about.

### C1 — Better · Drop Lenis and GSAP; keep one animation library

Lenis smooth scroll is the single biggest risk to the §19 budgets and to §20: it replaces the
browser's scroll loop with JavaScript (INP cost on every wheel event), breaks scroll anchoring,
find-in-page, scroll-snap on the arrivals rail, scroll restoration on back navigation, and
fights the View Transitions morph. The brief's one pinned scene does not need GSAP ScrollTrigger:
a 300 vh section with a `position: sticky` child and Motion's `useScroll` progress gives the
same scrub, with zero extra dependencies and ~35 KB gzipped saved. Everything else in §3.7
already uses Motion. Proposal: Motion only; native scrolling; pinned scene via sticky +
`useScroll`. If declined, I will integrate Lenis with ScrollTrigger as specified and measure.

### C2 — Fix · `--text-3` fails WCAG AA

Measured: `rgba(245,245,247,0.44)` on `#08080A` = **4.07:1**, below the 4.5:1 required for the
12–14 px captions it is used for (« taxes en sus » on cards, hints). At 0.50 it is 4.97:1 on
`--bg` and 4.96:1 on `--surface`. I set 0.50 in the tokens. All other pairs in the §3.2 table
check out (18.4, 4.97, 6.51, 4.03). `--white` on `--red` at 4.97:1 passes AA for the
16 px / 600 button label but is just above the line; the logo-sync step must re-check it.

### C3 — Fix · Two red buttons in the same view

§5.1 puts a red primary « Réserver un essai » in the nav; §6.1 puts a red primary « Voir
l'inventaire » in the hero; §8 puts one in the summary panel and §5.2 another in the mobile
sticky bar; §6.11 ends the home with one more. Several views would show two red buttons,
breaking §3.8 "one primary button per view" and the ≤ 3 % red budget. Proposal: the nav CTA is
a **Light** button (white on black) everywhere; the mobile sticky bar appears only once the
panel's primary button has scrolled out of view. Red stays with the content's single action.

### C4 — Fix · Schema details in §16

1. `vin char(17) unique not null`, `price_cad not null check (> 0)`, `body_type not null`,
   `condition not null`, `odometer_km not null` conflict with autosaved **drafts** and with
   "publish validation requires VIN, price, km". Proposal: nullable columns plus a check
   constraint `status = 'draft' or (vin is not null and price_cad > 0 and …)`, unique partial
   index on `vin where vin is not null`, and `text check (length(vin) = 17)` instead of `char`.
2. A column named `trim` collides with the SQL `trim()` function in expressions such as the
   generated `search` column. Rename to `trim_level` (API field stays `trim`).
3. Missing `demo boolean not null default false` on `vehicles` (§28.1 says records carry it)
   and a `gin(features)` index for the feature filters.
4. Missing a table for the daily AI budget (`ai_usage_daily`) and the search cache (A10).
5. `test_drive_bookings` needs `unique (vehicle_id, starts_at, lead_id)` and an index on
   `starts_at` for slot capacity counts.

### C5 — Fix · The displayed credit rate must be the APR including fees

§14 says mandatory credit fees are "included in the credit-rate calculation". With fees, the
disclosed *taux de crédit* is not the nominal rate: it is the rate that makes the payment
stream equal the financed amount, found by iteration (Newton / bisection). `lib/finance` will
expose both `nominalRate` and `disclosedRate` and unit-test the fee case. Without fees the two
are equal and nothing changes.

### C6 — Better · Legal warranty class can be suggested, not only typed

Québec classes depend only on vehicle age and odometer (A: ≤ 2 yrs and ≤ 40 000 km ·
B: ≤ 3 yrs and ≤ 60 000 km · C: ≤ 5 yrs and ≤ 80 000 km · D: otherwise). Admin can
pre-select the class from year + km with a visible "suggested" label; staff can override and the
client still confirms (§17.3). Thresholds live in Settings next to the texts.

### C7 — Note · Demo media volume (see A3)

Roughly 150–250 MB of frames cannot sit in `public/demo/` under git. Storage bucket proposed.

### C8 — Better · Render demo spins in Chromium, not headless Node WebGL

§28.3 says "headless three.js". Node has no WebGL; `headless-gl` is software-only and cannot do
the PBR reflections the studio look needs. Proposal: a Playwright script drives three.js in
real headless Chromium (available here) and screenshots the canvas 36 times. Same output,
better quality, no native build headaches.

### C9 — Note · Image pipeline needs an alpha mask for the shared crop box

§10.2 step 4 computes one crop box from the car's bounding box across frames. That bounding box
is only known when background removal (Photoroom) is on. With the toggle off, the pipeline
falls back to a fixed crop (configurable per vehicle) and a warning in admin. AVIF encoding of
8 outputs per 3 000 px frame is slow; the route handler processes one frame per request with
`maxDuration` set accordingly, which matches the brief's client-driven concurrency of 4.

### C10 — Note · Initial JS budget is tight

Next 16 + React 19 baseline is ~90 KB gzipped before any feature. next-intl, Motion
(`LazyMotion` + `domAnimation`), nuqs, the video player and the AI search bar must fit in the
remaining ~90 KB. Achievable if C1 is accepted and Car360 / assistant / calculator stay in
dynamic imports, but it will be measured and reported every phase.

### C11 — Better · Use Next 16 primitives already in the scaffold

The brief predates Next 16: `middleware.ts` is now `proxy.ts`; `revalidateTag` from a Server
Action should be `updateTag` for read-your-writes in admin; Cache Components (`'use cache'`,
`cacheLife`, `cacheTag`) replace `unstable_cache`. React 19.3 ships `<ViewTransition>`, so the
§3.7 card → page morph is no longer a risky enhancement. `cacheComponents: true` is enabled;
next-intl 4 supports it but requires passing the locale explicitly into cached functions,
which `lib/` will do by convention.

### C12 — Fix · Vehicle page title duplicates the brand

§18's template `%s | Idya Auto` plus the vehicle title `… | Idya Auto [city]` yields
"… | Idya Auto [city] | Idya Auto". Vehicle pages will use `title.absolute`.

### C13 — Note · Vercel Cron runs in UTC

The 8 a.m. digest (§27.4) will be scheduled hourly and sent when it is 08:00 in
`America/Toronto`, so DST changes do not shift it.

### C14 — Note · AV1 in Safari

Safari reports AV1 playback only on hardware that decodes it (A17 Pro, M3 and later), so the
H.264 fallback (§11.2) will serve most Apple devices. Source choice is done in JavaScript
(`canPlayType`) rather than `<source media>`, which is unreliable across browsers.

### C15 — Note · Placeholder cycling and reduced motion

The hero search placeholder that cycles every 3 s (§6.1) is motion; it will be static under
`prefers-reduced-motion` and will pause when the field is focused so screen readers are not
re-announced.

### C16 — Note · Hero media from Supabase Storage

Replacing the hero video from admin without a redeploy (§11.2) means poster and video are
served from the Supabase CDN domain, not Vercel. The poster is the LCP element, so the layout
adds `<link rel="preconnect">` for that origin and the poster keeps `fetchpriority="high"`.
